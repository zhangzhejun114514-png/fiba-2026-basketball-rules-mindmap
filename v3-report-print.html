1　摘要

本报告给出注入攻击检测表示体系的 v3 化简定义及其在 AgentDrift 与 MemEvoBench 上的完整验证。核心是把复杂的攻击语义收敛为 4 类事件节点 + 2 类可并存的关联边（时间先后 / 信息传导）；判定流程对每条轨迹回答三个问题——是否产生恶性结果、攻击源点在哪、从源点如何演化到结果。沿用中的 P1–P8 不再是预先枚举的模板，而是三问输出（尤其是 Q3 演化路径）的压缩标签。

主要结论

  1. 表示收敛成立。权限变化、资源流转、上下文诱导、推理传导等区分，全部可下沉为节点属性；模板判定所需信息由「逐 steps 遍历 + 标签」改为「节点属性 + 边」的表达，离线校验在 2,201 条轨迹上判定/模板/图统计 0 差异。
  2. 三问输出契约与既有判定逐条等价。新增薄派生层 _v3_analysis.py，仅由既有判定结果做步号算术：Q1（outcome = 已落地 / 未遂 / 无 + 危险动作性质）≡ 原 hit；Q2（primary 源点 + secondary 二次注入点）的源点 ≡ min(signal_steps)；Q3（源→结果的显式路径 + 形状）与 P1–P8 一一对应。2,201 条上三条等价全部成立，检测计算零改动、零 API。
  3. 低召回子型补丁有效。新增 P6（摄取传导）、P7（危险执行）、P8（伪装系统指令），仅在 P1–P5 未命中时启用。AgentDrift 结构 F1 0.849 → 0.908，精确率同向改善（0.930 → 0.937），825 条负样本零新增误报；MemEvoBench 结构 F1 0.294 → 0.678（ingestion 召回 7.3% → 92.7%）。
  4. 结构端与 LLM 判读端可低成本对齐。采用后置 OR（final = LLM_pred ∨ structural_P8），零 API 调用下合并 F1 0.874 → 0.902，召回 0.875 → 0.925，误报 0 新增。
一句话总结：表示层只有 4 类事件节点和两类可并存的边；对每条轨迹回答「是否产生恶性结果 / 注入源点（含二次注入点）在哪 / 从源点如何演化到结果」三问。P1–P8 只是 Q3 演化路径的压缩标签，不再是需要预先枚举的模板——叙事更简，且既有性能一项不丢。

2　背景与问题

2.1 威胁模型

LLM Agent 在工具调用轨迹中执行任务：读取用户指令、检索外部内容（网页 / 邮件 / 表单 / 记忆）、推理规划、调用工具、接收工具返回。攻击者在外部内容中植入指令（prompt injection），诱导 Agent 偏离原任务，产生未授权外发（数据泄露到外部目标）或有害执行（危险载荷落地执行）。

2.2 需要回答的三个问题

  • 表示：轨迹中哪些要素是"本质"的？能否用极少的节点/边类型覆盖全部攻击与良性行为？
  • 判定：如何从表示中稳定识别攻击？既要高精确率（负样本零误报），又要尽可能高的召回。
  • 对齐：结构化判据与 LLM 判读端如何在不大量消耗 API 的前提下取得一致？

2.3 前序工作与遗留问题

早期模板用抽象角色描述轨迹：不写具体节点类型，而把节点抽象成少数几个固定角色，再写角色之间的链式关系。记号简洁，但存在三个问题：

  • 与实现脱节。代码里已构建节点 U/Th/AC/TR 与边 E1/E2，但模板判定仍直接遍历 steps 并按 step 索引与 label 计算，图只进入报告统计（"装饰性"）。
  • 表达力单一。旧记号假定"一种攻击 = 一条线性链"，难以表达"一种攻击类型有多个典型模板"以及"信息摄取型"（无独立外发步、注入藏在观察/记忆中）等形态。
  • 角色抽象掩盖节点类型差异。同一个抽象角色在实现里可能落在三种不同节点类型上（用户指令被污染 / 观察被污染 / 推理被内化），把三者抹成一种，掩盖了它们其实是不同的模板。

本报告即针对上述三点，完成属性下沉 → 模板节点原生枚举 → 离线零差异校验的改造。

3　第一节 · 事件节点定义（U / Th / AC / TR）

轨迹被建模为一个有向图，节点是"事件"，边是"事件之间的关联"。节点只保留 4 类基础类型，其余区分全部下沉为节点属性。

表 3-1　4 类基础事件节点
节点含义来源字段承载属性（下沉）
U用户指令task（前置，step = −1）inducement
Th推理 / 思考step.thoughtinducement、refuse、sys、label
AC工具调用（动作）step.tool + step.argstool、args、action_type、resource_type、unauth_ext、harm、branch3、exec、mem、label
TR工具返回（观察）step.obsinducement、danger、novel、label

3.1 为什么是这 4 类

对 AgentDrift 12,536 条轨迹（225,608 个节点事件）与 MemEvoBench 83 簇做全量要素拟合，得到三条化简结论：

  • 四类节点即可覆盖全量要素。MemEvoBench 表示 sanity 中 4 类节点对轨迹要素覆盖率为 True（节点计数 {U:320, AC:848, TR:320}）。
  • 其余区分是"属性"而非"类型"。权限变化 / 资源流转（R1–R6）/ 上下文诱导 / 推理传导，都可作为节点上的布尔或枚举属性承载。
  • 属性是判定所需的最小信息。模板判定只读取节点属性，不再回读原始 steps。

4　第一节 · 关联边定义（E1 / E2）

边只保留 2 类，刻画节点之间最本质的两种关联；同一对节点可并存两类边。例如一条用户指令既传递了信息（其中的邮箱/URL 经 E2 流向后续动作），又触发了 Agent 的思考与动作（经 E1 指向后继 Th/AC）——两件事同时成立，就挂两条边，互不挤占。"时间先后"取相邻骨架而非全序：任意两点都有先后，全序边不携带额外信息，还会稀释"直接触发"。

表 4-1　2 类关联边
边含义判定
E1时间先后（相邻节点骨架）节点序列中相邻的两个节点直接相连：既含 U(step=-1) → 首事件，也含步内 Th → AC → TR；回答"谁先谁后、谁直接触发谁"
E2信息（数据）传导（类型化实体交集）节点文本的类型化实体交集非空：email / url / num / id（strict 档）；回答"什么数据从谁流向了谁"

4.1 E2 的抗噪设计

信息传导只承认类型化实体的交集，而不是任意词重叠。这样"同一封邮件地址 / 同一个 URL / 同一个编号 / 同一个 ID 从载体流向下游动作"才是传导，避免通用词造成的假阳性。

E2(i, j) ⇔ ents(text_i) ∩ ents(text_j) ≠ ∅ ents(·) = { (email, e) } ∪ { (url, u) } ∪ { (num, n) } ∪ { (id, t) } 其中 id 仅收录含数字 / 下划线 / 连字符的 token（天然抗噪）

5　第二节 · 三问输出契约（从表示到判定输出）

本章要点：表示层只有两种构件——节点（U / Th / AC / TR，其余区分全部下沉为节点属性）与两类可并存的边（E1 时间先后 / E2 信息传导）。除此之外不再预设任何"风险模板分类"。判定流程跑完后，对每条轨迹回答三个问题：
  Q1 当前执行路径是否产生了恶性结果；
  Q2 攻击的发起源点在哪里（以及次要 / 二次注入点）；
  Q3 从注入到结果事件是如何演化的。
沿用中的 P1–P8 只是 Q3 演化路径的压缩标签（为与历史指标连续而保留），不是需要预先枚举的模板分类。

标签的具体赋值规则与历史口径完全一致（只是换了个读法）：

5.4.1 路径标签 P1–P5

P1 n ∈ {U,Th,TR}[谓词 A] ─E1→ m ∈ AC[谓词 B] 检出：带信号节点 n 与危险动作节点 m 的 step 差 == 1（相邻）。 三种节点侧形态分别枚举：U[signal] ─E1→ AC[…]、Th[signal] ─E1→ AC[…]、TR[signal] ─E1→ AC[…] P2 n ∈ {U,Th,TR}[谓词 A] ─(step 差 ≥ 2)→ m ∈ AC[谓词 B] 检出：n 与 m 之间存在其它节点（隔步）。 P3 P1 的任一模式 ∧ ∃ 节点 k，step(k) > step(m) 且 label(k) == benign 检出：相邻命中，且危险动作之后仍有良性节点（攻击后回归正常流程）。 P4 ∃ n[谓词 A] ∧ ∄ m[谓词 B] ∈ 下游(n) ∧ ∃ Th[refuse] ∈ 下游(n) 检出：有带信号节点、下游无危险动作节点，但出现拒绝/警觉 → 未遂（failed_attempt）。 P5 ∄ n[谓词 A] 不命中：不存在带信号节点（no_signal）。

其中 下游(x) 取 step > step(x) 的全部节点。读作三问即：P1–P3 的 Q1=realized、P4 的 Q1=attempted、P5 的 Q1=none。

5.4.2 补丁标签 P6–P8

P1–P5 覆盖"带信号节点 → 危险动作节点"的路径型攻击，对信息摄取型（注入藏在网页 / 表单 / 记忆，无外发参数）失明。补三条按节点类型直接写出的机制型标签；它们仅在 P1–P5 路径未形成时启用，不改变 P1–P5 语义。

P6 摄取传导型 ∃ AC[mem] ∧ ∃ TR[novel]， 且 novel 实体出现在 ⋃_{step > 该 TR} AC.args 记忆节点存在（记忆介导）；载体 TR 引入"任务未提及实体"； 该实体被下游动作参数使用（实体在 AC.args 复现）。 效果：对非记忆轨迹零触发。 P7 危险执行型 ∃ TR[danger]，∃ AC[exec]（step > 该 TR） 某工具返回节点含危险载荷（shell 破坏 / 外联下载 / 凭证）， 且下游存在执行类动作节点 → 载荷被执行。 P8 伪装系统指令型 ∃ Th[sys] 某步推理节点把注入内容当作系统级指令内化，是部分注入（注入藏于观察、 无独立带信号节点）被 Agent 采纳的语言痕迹。 判据（RE_SYS）： \b(the\s+)?system\s+(suggest|recommend|advis|instruct|note| require|request|say|state|indicat|prompt)
为何 P8 是"机制签名"而非统计巧合：attacked_partial 的注入溶解在观察文本中（无独立带信号节点）→ 结构端判 P5、LLM 判 P5 漏检；但注入措辞伪装为"系统指令"，Agent 在 thought 中把它内化为"系统建议/要求"，从而留下 sys 语言痕迹。该痕迹只在 partial 注入场景产生，其余攻击子型与全部 825 条负样本零触发。

8.3 P8 的机制解释

P8 救回的漏检（53 条）全部为 attacked_partial，原因是机制性的，而非统计巧合：

  1. 注入溶解。partial 注入藏在观察文本中，没有独立的带信号节点 → 结构端无带信号节点、LLM 也读不到独立注入点 → 双端漏检（结构判 P5、LLM 判 P5）。
  2. 伪装为系统指令。注入措辞伪装成系统级指令，Agent 在推理中把它内化为"系统建议 / 系统要求"。
  3. 留下语言痕迹。这种内化只在 partial 场景发生，体现为 sys 信号；其他攻击子型无此语言特征，全部负样本零触发。

因此 P8 是攻击机制的语言签名，其触发集合与 attacked_partial 高度重合。

12　经验与教训

有效

  • 属性下沉 + 图模式让模板可读、可复现，且不损失性能（0 差异）。
  • "机制签名"优于"统计特征"：SYS 在 825 条负样本上零误报，是攻击机制的必然痕迹，而非阈值调参的产物。
  • 零调用后置逻辑（OR 合并）在判定差异场景下，可替代昂贵的全量重跑。
  • 精确率优先的规则准入，保证了新信号不引入代价。

无效 / 已否决

  • 基于 3-gram 新颖度的检测无效：hard_negative 的均值最高，无区分度。
  • COMPLY（伪造合规指令）：在良性委托句上误报 32 条，不适合作为通用规则。
  • CRED（凭证/危险命令词）：在 coding 良性样本上误报 10 条。

边界与局限

  • P8 只覆盖 partial。其 sys 痕迹是 attacked_partial 注入被内化的机制签名，其他攻击类型不具备该语言特征——这是它的收益来源，也是它的适用边界。
  • attacked_delayed 召回仍低（结构 41.8%）：延迟触发的注入不产生即时的 AC[目标] 节点，现有模板未覆盖。
  • MemEvoBench 精确率受标签噪声拖累（41% 误报本身含外发/敏感动作）。
  • QA 段结构不可达：无工具动作 → 无 AC[目标] 节点，需依赖 LLM 判读。
